# 多币种最新成交与大额成交监控

## 独立大额门槛与日志空间统计

现货和合约分别设置大额金额门槛（USDT）。`large_trade_usdt` 用于现货，`futures_large_trade_usdt` 用于合约；旧配置升级时两者默认沿用原门槛。修改只影响之后接收的成交，历史大额标记和当时门槛保持不变。

页面“日志空间占用”显示日志文件大小合计、文件数、现货/合约/历史备份/运行日志分类，以及日志所在磁盘总容量、剩余空间。统计包含数据库和 WAL、小时 CSV、备份、旧数据库和运行日志，不只计算页面最近显示的记录。每 30 秒更新，可手动刷新；读取失败会提示数据可能不完整或过期。文件大小使用二进制 KiB/MiB/GiB，与文件系统实际分配大小可能不同。

磁盘剩余低于 5 GiB 或 10% 时显示提醒，不自动删除数据或停止采集。磁盘空间不是运行内存 RAM，剩余空间包含同一磁盘其他程序的占用。接口：`/api/storage`，`?refresh=1` 强制刷新统计。

## 现货与合约

在“监控市场”中选择仅现货、仅 USDT 永续合约、或现货 + 合约同时监控；两类市场分别填写自定义交易对（例如 XRPUSDT、BTCUSDT），各支持最多 20 个。点击应用后生效。旧配置自动兼容，默认保留仅现货及原有币种、金额门槛。

两类市场独立连接、重连、去重和保存。同名交易对的成交编号不会冲突。现货历史数据仍使用原路径 `logs/XRPUSDT/日期/`，合约日志使用 `logs/futures/XRPUSDT/日期/`；CSV 增加 market 字段。历史搜索新增市场选择，CSV 导出也区分市场。关闭某类监控不会删除它的历史记录。

现货使用逐笔 trade 流；合约使用 aggTrade 流，大额金额按每条聚合成交的价格 × 数量计算。合约记录由币安按相同价格与主动方向聚合，不能直接与现货逐笔数量比较，不能视为完整大户订单。主动买入/卖出不代表开多/开空，公开成交不能区分开仓和平仓。本版本不含币本位、交割合约和爆仓专用流。

合约数据源：`wss://fstream.binance.com/market/stream`。[币安合约聚合成交文档](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/ws-streams/market)。

## 开启与停止

- 双击 `开启服务.bat`（或 `start.bat`）：后台启动并打开网页，重复点击不会启动多个采集程序。关闭启动窗口不影响后台。
- 双击 `停止服务.bat`（或 `stop.bat`）：先停止接收成交、保存待提交日志，再完全关闭后台服务；再次运行会提示已经停止。
- 网页“停止监控”：停止采集并保存日志，网页和历史查询仍可使用。
- 网页“开始监控”：恢复采集。
- 完全关闭后台后，需要使用启动脚本重新开启；仅关闭网页不会停止后台。暂停期间的成交不会回补。

命令行也可用 `python service.py start` / `python service.py stop`，可附加 `--port` 指定端口。直接运行 `python monitor.py` 时仍可按 Ctrl+C 正常停止并保存日志。

## 时间范围搜索

页面“历史成交查询”可选择币种、开始时间、结束时间，以及全部成交/仅大额成交。时间统一按北京时间解释，包含开始时刻、不包含结束时刻，可跨小时和日期。支持查询已停止监控但仍有本地记录的币种。

每页 100 条，按成交时间从新到旧排列。翻页和“导出该时间段全部结果 CSV”使用同一次查询的数据快照；新写入记录需重新点击搜索才能纳入。导出包含该查询的全部结果，不只当前页。大额成交按记录当时的门槛判断。只能查询本程序已保存的数据，不补取启动前或断线期间未记录的成交。

## 最新：按日期和小时保存日志

自动 CSV 日志现在按交易对、北京时间成交日期和小时拆分，例如：

```text
logs/XRPUSDT/2026-11-05/trades_13.csv
logs/XRPUSDT/2026-11-05/large_trades_13.csv
logs/XRPUSDT/2026-11-05/trades_14.csv
logs/LTCUSDT/2026-11-05/trades_13.csv
```

`13` 表示 13:00:00–13:59:59，每小时的普通成交和大额成交分别保存。无成交的小时不生成空文件；延迟到达的成交按其成交时间归入对应文件。所有历史记录也按此规则恢复，重启不会重复追加。原有单个大 CSV 转移到 `logs/legacy/` 保留备份，不再继续追加。内部 SQLite 继续作为去重和恢复数据源。

页面的“导出”仍是对应币种的完整历史导出，可能较大；需要小文件时直接打开上述小时日志。

## 更新：记录按币种分开

页面现在按币种独立分组，每组分别显示最新成交、大额成交及各自的导出入口。下文旧的合并导出地址已停用，改用 `/api/export/XRPUSDT/trades.csv` 和 `/api/export/XRPUSDT/large.csv`；替换交易对即可导出其他币种。

本地自动日志也已分开：`logs/XRPUSDT/trades.csv`、`logs/XRPUSDT/large_trades.csv`，BTC、ETH 等各有同名目录。约每秒更新；启动时从历史数据库恢复，旧记录保留。文件被 Excel 独占时请关闭后等待重试。自动 CSV 的 time 字段为毫秒时间戳；下载 CSV 另外包含上海时区时间。内部 SQLite 仍用于去重和恢复，不影响各币种独立文件。

## 启动

Python 3.9+。首次使用先运行 `python -m pip install -r requirements.txt`，然后双击 start.bat 或运行 `python monitor.py`。打开 http://127.0.0.1:8765 。端口可用 `--port` 指定。Ctrl+C 停止后台。

## 同时监控多个币种

默认 XRPUSDT、BTCUSDT、ETHUSDT，保留原有 20,000 USDT 大额门槛。交易对用逗号、中文逗号或空格分隔，最多 20 个；可输入 XRP/USDT。支持 USDT 交易对，所有币种共用一个大额门槛。

页面“显示币种”仅筛选展示，不影响其他币种采集。列表显示最近 100 条；后台保留所有成功写入的记录。每个币种显示最近接收时间；若某币种一直等待成交，请检查交易对是否存在或已经下架。

## 日志

- `logs/trades.sqlite3`：持久化成交日志，trades 表保存全部成交，large_trades 视图提供大额成交日志。
- 字段包含币种、成交编号、成交时间、接收时间、主动方向、价格、数量、USDT 金额、大额标记、当时使用的门槛。价格和金额使用十进制计算并以文本保存。
- 按币种 + 成交编号唯一去重。不同币种即使编号相同也分别保存。
- 全部成交 CSV：http://127.0.0.1:8765/api/export/trades.csv
- 大额成交 CSV：http://127.0.0.1:8765/api/export/large.csv
- CSV 包含所有历史币种，不受当前筛选或监控列表限制，UTF-8 BOM 编码可供 Excel 打开，含上海时区时间。
- `logs/service.log`：连接、错误及设置变更日志，5 MB 轮换，保留 3 个备份。

历史记录不会因刷新页面、重启程序、移除币种或修改门槛而删除。修改门槛仅影响之后接收的成交，历史大额标记按原门槛保留。成交日志不自动清理，请留意磁盘空间。备份数据库前先正常停止程序，或使用 SQLite backup 工具；运行时 WAL 文件可能包含尚未合并的记录。

## 后台工作方式与边界

Python 后台通过币安 WebSocket combined trade streams 同时订阅多个币种。关闭浏览器仍然采集和写日志；关闭后台程序或电脑休眠会停止采集。页面每秒读取本地日志缓存，打开多页不会重复订阅。

按约 250ms 或 2000 条一批提交 SQLite，低成交频率时最迟约一秒刷新。正常 Ctrl+C 会写完待提交批次；强制结束进程或断电可能丢失未提交批次。断线自动重连，但不回补断线期间的历史成交；服务日志会标记重连。磁盘写入失败将显示错误，持续失败会停止采集，不伪装为记录成功。

大额按单笔撮合价格 × 数量判断，不等于一个大户的完整订单。买方为 maker 时标记主动卖出，否则主动买入。公开成交无法区分现货与杠杆账户。

桌面通知需页面保持打开并获得权限；通知按页面轮询到的大额记录合并提示，不保证覆盖瞬间超过页面保留数量的全部事件，完整记录以数据库和 CSV 为准。

## 网络

数据源：`wss://data-stream.binance.vision:443/stream?streams=...`，无需 API Key。使用 websocket-client 1.8.0，支持系统 HTTP CONNECT 代理，或 `HTTPS_PROXY=http://host:port` 环境变量。不会关闭 TLS 证书校验。若 pip 因系统代理配置安装失败，可显式指定 `--proxy http://host:port`。
